# 24 -- Open-source readiness

> **ID** MP-24 · **Status** Draft · **Depends on** -- (can start now, in parallel) · **Unblocks** making the repository public

**Agent brief.** Prepare the repository to be public: choose and apply the license, add governance and community files, audit the
history and dependencies, and remove anything private. Several steps are **owner-only** (relicensing, making the repo public, enabling
GitHub features); produce the checklist, files and scripts for everything else. Do not change the license until the owner confirms Q7.

## Context

- `LICENSE` is currently proprietary ("All rights reserved") and the README badge says so. Making the project open source is a deliberate legal act by the copyright holder.
- The GitHub repository was renamed (`origin` still shows `duevia-ledger`, which redirects). The README CI badge still uses the old name.
- Open-source Android distribution needs permissive or store-compatible licensing: F-Droid requires an OSI-approved license; GPL/AGPL are widely reported to conflict with Apple's App
  Store terms, which matters for the planned iOS app **(verify with the current App Store and license-compat guidance)**. Hence the default recommendation of **Apache-2.0** (patent grant, store-friendly) or MIT.

## Requirements

1. **License**: after the owner answers Q7, replace `LICENSE`, update the README badge/section, add SPDX identifiers (`SPDX-License-Identifier: Apache-2.0`) to source headers only if the owner wants them (a `LICENSE` + `NOTICE` file is sufficient; avoid noisy header churn), set `"license"` in each `package.json` and `pyproject.toml`.
2. **Copyright holder**: confirm that the owner holds copyright for all existing code (including any contributions by others). If any third-party contributions exist, get their consent or remove them. Record the decision.
3. **Contribution terms**: use the **DCO** (`Signed-off-by`) rather than a CLA unless the owner wants a relicensing right; document it in `CONTRIBUTING.md`; add a check (the DCO GitHub app or a small workflow **(verify)**). Note the existing commit-lint hook and conventions must keep working; sign-off is a footer line.
4. **Community files**: `CODE_OF_CONDUCT.md` (Contributor Covenant), `SECURITY.md` (MP-18), `GOVERNANCE.md` (benevolent maintainer model, how decisions and releases are made, how to become a maintainer), `SUPPORT.md` (where to ask questions, what is not supported), issue templates (bug, feature, security redirect) and discussion categories, updated `CODEOWNERS`.
5. **README rewrite for the public**: what it is, screenshots (generated from invented demo data), the three ways to run it (Android local, self-host cloud, web), privacy promise, install channels, architecture link, contributing link, license. Keep the existing developer quick-start. Remove the proprietary badge.
6. **Third-party license inventory**: a script (`npm run check:licenses`) that lists all production dependencies (npm and Gradle) with SPDX ids, fails on anything outside an allow-list (MIT, ISC, BSD-2/3, Apache-2.0, 0BSD, CC0, Unlicense, OFL for fonts, MPL-2.0 case-by-case) **(owner to confirm list)**, and generates the in-app "Open-source licenses" screen data and `THIRD_PARTY_NOTICES.md`.
7. **Content audit**: no real personal data in fixtures/screenshots/sample data (`backend/tests/support/sample_data.py`, seed file, docs examples use invented names and `example.com` emails); the `supportEmail` default is a placeholder; check the `archive/` docs folder for internal notes before publishing.
8. **Secrets and history audit**: run `detect-secrets` and a full-history scanner (e.g. gitleaks/trufflehog **(owner picks)**) over **all branches and tags**; rotate anything that was ever exposed, and say so (AGENTS.md rule 5). Check large files and `.env*` in history. If history contains something unfixable, publish a squashed fresh history instead (owner decision).
9. **Name and branding**: search for conflicts with the name "Monetary" in app stores and trademarks **(owner/legal)**; publish a short `docs/brand.md` (name usage, logo license, no implied endorsement for forks). All icons/artwork must be original or properly licensed; keep source files for the icon in the repo.
10. **Repository settings (owner)**: branch protection on `main`, required checks, required reviews, disallow force-push to `main`, private vulnerability reporting, Dependabot alerts, secret scanning + push protection, GitHub Discussions, Pages (for the privacy policy and docs), CODEOWNERS enforcement, repo description/topics.
11. **Docs site (optional)**: publish `docs/` via GitHub Pages; at minimum the README links resolve on GitHub.
12. **Release hygiene**: `CHANGELOG.md` stays generated by release-please (never hand-edit); tag the first public release `v1.0.0` only when the success criteria of MP-00 are met; earlier ones are `0.x` pre-releases.
13. **Sustainability notes**: contribution guide for AI-assisted contributions (AGENTS.md already governs agents; state in `CONTRIBUTING.md` that contributors are responsible for what they submit, and that no tool attribution lines go in commits, per the repo owner's rule).

## Acceptance criteria

- `LICENSE`, `NOTICE`/`THIRD_PARTY_NOTICES.md`, package metadata and README agree on the license.
- `npm run check:licenses` passes and generates the notices file; a deliberately added GPL dependency makes it fail (test).
- Secret scanning of all history reports nothing unresolved.
- A new contributor can follow README -> CONTRIBUTING -> a work-package doc and open a valid PR without asking questions (dry-run by someone who has not seen the repo).
- Owner checklist is complete before the repository visibility is changed.
